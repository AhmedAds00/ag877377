# Content log

A plain Markdown file that records every Reel package the creator has received. Its purpose is to prevent repeated topics and hooks, and to let the creator track results over time.

## Location

Use `content-log.md` in the creator's working folder. If the creator names another path, use that instead.

## Format

Keep one table. Add a new row for every package delivered. Do not rewrite old rows except to fill in metrics the creator later provides.

| Date | Topic | Hook (first line) | Angle | Length (sec) | Score | Published | Views | Saves | Shares | Lessons |
|---|---|---|---|---|---|---|---|---|---|---|

Rules:
- Date uses the creator's local date (Asia/Kuwait by default) in YYYY-MM-DD format.
- Hook column stores only the first line, so the log stays compact.
- Leave Published, Views, Saves, Shares, and Lessons empty until the creator provides them. Never invent numbers.
- Lessons holds one short sentence from performance analysis, if any.

## Workflow

1. **Before generating ideas or a package:** if the log exists, read it. Skip topics and angles already used, and avoid hooks with the same opening structure.
2. **After delivering a package:** add a new row. Use Write only if the file does not exist yet; otherwise use Edit to add one row at the end of the table.
3. **Confirm the save:** only say "أضفته للسجل" after the file operation succeeds. If it fails, say so and offer the row as text the creator can paste.

## Creating the file for the first time

Create the file with the header row and the table separator, then add the first entry. Keep the file under about 200 rows; when it grows beyond that, summarize older rows into a short "Older themes" paragraph at the top, and keep the most recent 50 rows as a table.
